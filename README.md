# Opening Trainer

Play through chess openings yourself. Pick an opening and a side; the computer answers with a **random book line**, and every move you make is graded:

* **Book move** – it's in the opening line.
* Otherwise **Stockfish 19** (WASM) compares your move with its best move and labels it
  **Best** (≤10 cp loss or the engine's top move) · **Excellent** (≤25) · **Good** (<50) · **Inaccuracy** (50–100) · **Mistake** (100–250) · **Blunder** (>250).
* You always see the expected book move(s), the evaluation, and the engine's best move, and can **Retry**, **Show book move & continue**, or (for sound moves) **Keep my move (leave book)**.
* Score: Book/Best 100 · Excellent 90 · Good 75 · Inaccuracy 40 · Mistake 15 · Blunder 0 per move, based on your *first try*. A hint caps that move at 50. A summary appears at the end of each line.

## Run it

**Best (full Stockfish): a local server**

```bash
./serve.sh            # → http://localhost:8080/   (or: python3 -m http.server 8080)
```

**Or just double-click `index.html`.** Browsers don't allow web workers from `file://`, so the app falls back to a small built-in JS engine (depth-2 search); grading still works but is rougher. The pill in the top-right shows which engine is active.

No internet or build step needed — everything is bundled in this folder.


## Editing / rebuilding

```bash
npm install
./build.sh            # rebuilds dist/app.js with esbuild
npm run test:book     # validates every book line is legal
npm run audit         # Stockfish check that no book move drops >70 cp
npm run test:e2e      # headless Chrome tests (needs the server at :8099 or pass a URL)
npm run test:gambits  # plays every gambit through the UI; every book move must grade as Book
npm run test:touch    # emulated-iPhone touch drag / tap-select / snap animation
ONLY=gambit THRESH=120 npm run audit   # audit only the gambits (sacrifices are expected to show up)
```

To add a line, append `{ name, moves: 'e4 e5 Nf3 ...' }` (SAN, no move numbers) to an opening in `src/openings.js` and rebuild. Lines merge into a position graph, so shared prefixes and transpositions just work.

## Gambits

Openings with `gambit: true` show up under the **♟ Gambits** filter in the picker (the other filters are by side). Gambit lines give up material on purpose, so grading is **book first**: a move that is in the book is *always* graded Book — the engine is never asked about it, so a sacrifice can never be marked down. Only moves **outside** the book are engine-graded (and the feedback card reminds you of that in gambit lines).

`src/gambits.js` is generated from verified base sequences (ECO names/moves from lichess-org/chess-openings, CC0) extended a few plies with Stockfish's top moves — see `tools/gen-gambits.mjs`. The generated lines are ordinary data: edit them by hand if you prefer other continuations.

There are 32 gambits: 17 to play as White and 15 as Black (all 16 classical openings and 32 gambits = 48 openings). Besides the classics (Fried Liver, King's Gambit, Evans, Danish, Scotch Gambit, Smith-Morra, Budapest, Benko, Albin, Englund, Stafford, Vienna, QGA, Latvian, Blackmar-Diemer, Halloween, Jerome, Traxler) it now covers Schliemann, Marshall Attack, Icelandic-Palme, Elephant, Von Hennig-Schara, Rousseau, Fajarowicz and Blumenfeld for Black, and the Wing Gambit, Göring Gambit, Staunton Gambit, Muzio Gambit and Belgrade Gambit for White. Each has several branching lines, a rating range, a play-style tag, a Watch-it-first walkthrough and a Learn-more popup.

## Piece lift (chess.com-style)

`src/lift.js` + the `piece::before` rules in `css/app.css`. A tapped piece hovers slightly; a piece in hand scales up (1.22× mouse, 1.4× touch), gets a drop shadow, sits a little above the finger on touch, the legal target square under it is highlighted, and on release it eases onto the square. The artwork is drawn on a pseudo-element so chessground's own `translate()` positioning isn't disturbed. Respects `prefers-reduced-motion`.

## Watch it first + Learn more

- **▶ Watch it first** (button on every opening card, and in the bottom bar for the selected opening): `src/demo.js` plays a line on a view-only board with arrows (green = move, red = capture, blue = castled rook, red ring = check), the last-move highlight and a plain-language note per move. Controls: play/pause, next/prev (also ←/→/Space/Home), restart, speed (0.6×/1×/2×), click any move chip to jump, and a line picker for every line of the opening. **Start practicing** jumps straight into the drill.
- **📖 Learn more** (opening card, the demo and the drill): `src/learn.js` shows the idea, plans for both sides, key squares/structure, traps & mistakes and who plays it. During a drill it also shows a "This position" note about the last move played (it never reveals the next book move). Closes with ✕, "Got it", Escape or a tap on the backdrop.
- Content lives in `src/lore.js` (`WALK`: hand-written per-move notes for each opening's main line) and `src/lore-text.js` (`LORE`: the popup text). Lines other than the main line, and moves beyond the written notes, get a factual generated note (`src/explain.js`: develops/castles/captures/check/what it attacks).
- `npm run test:lore` replays every note against the real line (the SAN in each note must be the move played at that ply) and every trap line shown in the popup (legal, and mate when it says mate). `npm run test:learn` is the browser test (all 48 popups; all 258 lines play to the right final position; controls; phone-size layout).

## Descriptions + recommended ratings

`src/meta.js` holds, for every opening, a one-line description, a recommended rating range (the pill on each card, colour-coded: Beginner < 1000 green, Intermediate 1000–1599 blue, Advanced 1600–1999 purple, Expert 2000+ red; the level is set by the low end of the range), a short "why", and a `trappy` flag for fun/surprise openings that stop working against strong, prepared players (those top out at ~1400). The picker has a **Rating** filter that combines with the side/gambit filter, and the Learn-more popup repeats the description, range and reasoning. `npm run test:lore` validates the data; `npm run test:ratings` is the browser test.

## Play style

Every opening has one of five fixed styles in `src/meta.js` (`STYLE`): 🔥 Aggressive (attacking, sacrifices), ⚡ Sharp (tactical, double-edged), ⚖️ Balanced (classical, flexible), 🧭 Positional (slow manoeuvring), 🛡️ Solid (safe, defensive). It shows as a pill on the card next to the rating pill, as a one-sentence "what to expect" in the Learn-more popup, and as a **Style** filter in the picker (combines with side / gambit / rating filters and is remembered). `npm run test:lore` checks every opening has a valid style and a one-sentence note; `npm run test:style` is the browser test.
